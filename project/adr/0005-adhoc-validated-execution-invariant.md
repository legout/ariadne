# Ad-hoc metrics: from governed-only to no-unvalidated-execution

Status: accepted (owner, 2026-09-14 shape-design round for spec revision 3).

The MVP's original invariant was "get_metric accepts only named governed metrics — never raw SQL" (spec rev 1/2 §6). The owner requirement that any data in the attached database be queryable — with the LLM generating new metrics on the fly and the semantic/context layers as helpers rather than gatekeepers — broke that invariant. Revision 3 replaces it with **no unvalidated execution**: agents may author dataset sources and metric expressions as structured `define_metric` params, but the facade expands them into an ephemeral OSI model and every computation still passes the deterministic Datus compile gate; there is no code path from tool arguments to `duckdb.execute` that bypasses the compiler. In this local ad-hoc workflow, governed state changes only by human Promotion; successful ad-hoc definitions are auto-staged as proposals, never auto-promoted. For production semantic models, the owner later approved human-reviewed, validated Git admission as a second gate ([ADR-0003](0003-staging-dir-review-gate.md)); it does not make an ad-hoc result governed. Agent-authored SQL fragments remain a named, accepted trust boundary until the deferred governance work.

**Considered options:** LLM drafting inside the facade (rejected — nondeterminism and LLM dependency inside the server; the consuming agent already is one); raw SQL tool (rejected — reintroduces ungoverned text-to-SQL, the failure mode the architecture exists to prevent).

**Later scoped amendment (owner, 2026-10-08):** [ADR-0019](0019-bounded-record-query-boundary.md) and [specification 0014](../specs/2026-10-08-0014-bounded-record-queries-and-results.md) add a separate ungoverned record operation that creates no metric or Proposal. Shared output preflight precedes ad-hoc staging: output refusal is not a successful answer and stages nothing, even if computation succeeded. Compiler/source/admission boundaries remain binding; result caps do not repair the separately reported SELECT-source containment defect. This is design capture, not implementation or publication authorization.
