# Usability shell: onboarding and discovery commands compose the gates, never bypass them

**Accepted scoped Git-only amendment (2026-10-16):** [Specification 0027, written revision 1](../specs/2026-10-16-0027-core-git-only-authoring.md) captures the owner-approved bounded Core direction; the owner approved the complete written revision and these scoped amendments with “Schriftliche Fassung freigeben (Recommended)”. Setup/status/discovery/review compose only the Git route, without a legacy/Promotion branch; source-free reporting, no implicit Git configuration and human authority remain. Unaffected original approval remains; no implementation or shared #76 contract is approved by this notice.

Status: accepted, revision 2 (Owner accepted this decision on 2026-10-12 by explicitly authorizing implementation of issues #62–#65, together with specifications 0016–0019 and the scoped spec-0001 usability amendment. Implementation authority does not include target integration, push, release or publication).

Ariadne's onboarding today is a sequence of separately documented commands (`ariadne-init`, source editing, `ariadne-author`, `ariadne-promote` or the Git proposal loop, `ariadne-skill install`), and discovery requires knowing four search commands. The 2026-10-12 ktx comparison showed this ceremony — not any missing governance — is the adoption gap. The risk in closing it is the obvious shortcut: let convenient commands quietly do what the gates exist to prevent.

Decision: one architectural constraint for all ergonomics work.

1. **Composition and shared seams.** Reuse artifact parsers, source-identity resolution, search functions and review/admission checks instead of duplicating them. Status needs a diagnostic path usable before admission; search needs shared artifact-only discovery without constructing the execution-opening QueryRuntime. These are explicit additions, not claims that the existing query adapter already provides them. Existing query root selection, admission refusals and execution remain unchanged.
2. **Human authority unchanged.** Setup never invokes source approval, admission, Promotion, reconciliation or merges; it stops the source/authoring pipeline and hands the required decision to the operator. Only the operator-only review walkthrough may cause admission/Promotion following an explicit final human confirmation of the displayed candidate. Managed mapping choices are collected before that confirmation and one admission call; legacy keeps the unchanged promoter's own final human prompt, never `--yes`. The delegate retains every existing check and records the same human decision; it has no independent approval authority and never writes served artifacts directly.
3. **Terminal is a UX condition, not identity.** The walkthrough requires interactive terminal input/output for confirmation; non-interactive runs display the review and remaining human commands only. A TTY is not proof that the caller is human. The operator-only skill rule and exclusion from MCP/native agent toolsets still apply; an agent answer is never a human decision.
4. **No additional ambient cost.** No telemetry, background daemons or new runtime dependencies. Status, detection and discovery make no network or source connections. A deliberately selected authoring step may use its existing operator-authorized source access and configured LLM endpoint; those accesses and data egress are disclosed before invocation, never performed as a readiness probe.
5. **Scoped usability output.** The proposed amendment in [spec 0001](../specs/2026-09-23-0001-local-artifact-runtime.md) permits human-first output only for the four new shell commands, with structured `--json` for status/search. Existing query commands retain their exact JSON/error contracts. The amendment requires owner approval with these proposed specs.

Behavioral contracts: [spec 0016](../specs/2026-10-12-0016-project-status-command.md), [spec 0017](../specs/2026-10-12-0017-setup-onboarding-wizard.md), [spec 0018](../specs/2026-10-12-0018-unified-discovery-search.md), [spec 0019](../specs/2026-10-12-0019-human-review-walkthrough.md). The gates they compose stay owned by [ADR-0003](../adr/0003-staging-dir-review-gate.md), [ADR-0005](../adr/0005-adhoc-validated-execution-invariant.md) and [ADR-0016](../adr/0016-modular-core-git-authoring.md).

**Considered options:** soften the gates for a friendlier "easy mode" (rejected — the gates are the product's reason to exist; a bypassed admission is indistinguishable from no admission); duplicate resolution/validation logic inside the wizard for speed (rejected — two implementations of one behavior drift, and the drift would surface exactly at the trust boundary); a prompt/TUI dependency for richer interaction (rejected for v1 — plain stdin prompts carry the flow, and the dependency policy stays minimal); do nothing (rejected — the ktx comparison evidenced onboarding friction as the concrete, addressable gap; distribution via PyPI is already done).
