AREA 1 — Governed structured data flow
Verdict: FULL
The path is real end-to-end, although deliberately multi-stage. An upload is content-hashed and persisted (`W/intake.py:59-95`); `prepare_data_source` converts uploaded bytes or materializes a bounded S3 prefix, then stores source identity, schema, samples, exclusions, and authorization (`W/analytics.py:149-247`). Human source approval and the separate data grant are distinct exact-binding operations (`W/analytics.py:249-413`). Profiling produces sample-column counts, min/max/null evidence, uniqueness ratios, bounded top values, and correlated pairs rather than decorative metadata (`W/analytics.py:415-545`).
The agent then stages a native contribution; source approval precedes submission review and overall publication (`W/analytics.py:547-727`). Only a successfully activated proposal becomes queryable (`W/analytics.py:981-1026`). Query execution resolves the pinned admitted snapshot and rechecks its identity and integrity (`W/analytics.py:1028-1063`; `D/query.py:1500-1519`; `D/admission.py:1325-1398`). Tools expose structured metric/dataset/detail/record operations, not caller SQL (`W/analytics.py:1003-1008`; `D/query.py:978-981`). Compiled statements pass a single-statement gate and deadline-guarded execution (`D/execution.py:200-234`, `D/execution.py:250-283`).
The connector coverage is substantive: SQLite, DuckDB, CSV/JSON/Parquet, Delta, Iceberg, DuckLake, and Postgres are explicit source implementations (`D/sources.py:11-25`). Workbook selection is explicit and cached without recalculation (`W/analytics.py:75-148`). S3 handles have namespace-scoped identities, explicit tables/prefixes, exact matching, and grant-bound storage identity (`W/analytics.py:604-665`, `W/analytics.py:673-704`). Result size limits remain native defaults, discussed in AREA 5, but do not break the data path.

AREA 2 — Shared published knowledge
Verdict: PARTIAL
The standalone SDK is strong: `KnowledgeBase` loads compiled pages, supports exact/alias lookup, full-page reads, and lexical search (`K/knowledge_base.py:423-492`, `K/knowledge_base.py:601-614`). Published filesystem and S3 locations resolve exact versions and verify manifests/fingerprints (`K/location.py:110-147`, `K/location.py:317-367`). Scoped context navigation implements list/read/search over only visible pages and returns canonical excerpts with line and section coordinates (`K/ariadne_context.py:2277-2299`, `K/ariadne_context.py:2302-2330`, `K/ariadne_context.py:2333-2369`).
Optional vector retrieval is also real: LanceDB stores embeddings, runs cosine vector search, filters by score, and can fuse lexical and semantic rankings (`products/lumio/packages/lumio-lancedb/src/lumio_lancedb/index.py:667-717`, `products/lumio/packages/lumio-lancedb/src/lumio_lancedb/index.py:723-747`, `products/lumio/packages/lumio-lancedb/src/lumio_lancedb/index.py:886-923`). The CLI exposes lexical/semantic/hybrid modes (`K/cli.py:8299-8344`, `K/cli.py:2981-3043`).
The shared workspace itself has no knowledge reader. Its only use of the admitted destination is constructing `EnrichmentService`; its MCP tools are upload, task polling, source preparation/grant/profile/query, and contribution preparation (`W/app.py:392-426`). There is no list, page, search, or retrieve tool, and `lumio-workspace` does not depend on `lumio-lancedb` (`products/lumio/packages/lumio-workspace/pyproject.toml:8-16`). Agents can submit knowledge they cannot subsequently find or read through that workspace.

AREA 3 — Human-in-the-loop review and notification
Verdict: PARTIAL
Review security and evidence are implemented. Review requires the `review` capability, exact candidate/base/publication bindings, a single-use action digest, and normally a reviewer different from the submitter (`W/review.py:171-187`, `W/review.py:267-299`, `W/review.py:366-426`). Approval activates only the reviewed candidate; rejection/request-changes does not publish (`W/review.py:511-568`). The page displays source support, exact content diffs, semantic/Claim changes, validation and blocking diagnostics (`W/review.py:896-1005`). Browser-only and agent credentials are separated at the HTTP boundary (`W/app.py:326-365`), and browser review accepts only the browser actor (`W/app.py:706-750`).
Notification is absent. State can fetch a known task for its submitter or reviewer, but has no list, subscription, or notification mechanism (`W/state.py:466-489`). The only routes are uploads, setup, a known `/review/{task_id}`, membership, auth, and status (`W/app.py:606-642`, `W/app.py:706-777`, `W/app.py:906-931`). A reviewer must receive a task UUID out of band; no durable queue or event tells them work is waiting. Therefore the named review-and-notification area is not implemented as a whole.

AREA 4 — Recurring agent workflows
Verdict: MISSING
No production code rechecks sources, submits changed documents, revisits findings, or recaptures evolving work. Source-refresh impact exists only while rendering an already-submitted candidate (`W/review.py:777-827`); enrichment selects a fixed admitted version and explicit pages (`W/enrichment.py:164-197`). Neither is an ongoing agent workflow.
The sole coding-agent client is Pi. It uploads one file, waits for an idempotent preparation result, and prints a review URL (`P/index.ts:100-159`); connect merely configures MCP (`P/index.ts:41-88`). Session start checks token presence, not work queues (`P/index.ts:260-271`). No Hermes or OpenCode workspace client exists under `products`; the only client package is private `@lumio/pi-workspace` (`P/package.json:1-8`). Shared contribution and query tools are prerequisites, not a recurring capture/review/recapture system.

AREA 5 — Complexity and failure modes
Verdict: PARTIAL
Durability and least privilege are conscientiously implemented: atomic/fsynced state writes (`W/state.py:202-230`), explicit capabilities (`W/state.py:49-70`), scoped token checks (`W/app.py:306-364`), and operation locks/journals (`W/state.py:434-464`). The native publication/admission gates are unusually thorough.
However, the low-bureaucracy goal fails. A new structured source requires upload, source preparation, source approval, data-grant approval, profiling, contribution preparation, submission approval, overall publication approval, then query: nine operations, four browser decisions (`W/analytics.py:149-171`, `W/analytics.py:249-307`, `W/analytics.py:332-411`, `W/analytics.py:547-571`, `W/analytics.py:674-727`). Profiling exposes only `sample_rows` (maximum/default 100), with no workspace row/response/deadline configuration (`W/analytics.py:14-24`, `W/analytics.py:104-148`, `W/analytics.py:546-571`). Approval is exact but not incremental: a correction creates another review generation and fresh action (`W/review.py:526-567`).
Restore is not smallest-part recovery. It replaces the entire admitted destination before validating state, clears all data-source grants, and rewrites the complete operation journal (`W/operations.py:168-213`). If copied state does not match the destination, it raises only after admitted documents were already replaced (`W/operations.py:195-212`). A torn restore can destroy the currently readable publication and every grant instead of preserving the smallest safe state.

MISSING
- Any workspace list/search/page/read/retrieval surface and workspace LanceDB integration.
- Reviewer notifications, subscriptions, and a pending-work queue.
- Recurring capture/review/recheck/recapture workflows and Hermes/OpenCode adapters.
- Incremental reviewed updates and non-destructive, grant-preserving partial recovery.

OVER-COMPLICATED
- Four separate human approvals for first-use structured data, with no equivalent reviewed update shortcut.
- Fixed profiling/execution bounds requiring native-layer changes rather than reviewed configuration.
- Full-destination/full-state restore where verified state reconciliation would preserve availability and least-privilege grants.

OVERALL
Verdict: PARTIAL
The native SDK, governed analytics pipeline, exact human review, authentication, and durable operation machinery are substantial and real. The central shared-team experience is incomplete: the workspace cannot read or search its admitted knowledge, cannot notify reviewers, and has no recurring agent workflow. Heavy first-use approvals and destructive whole-workspace restore further contradict the stated bureaucracy and failure-isolation goals.
