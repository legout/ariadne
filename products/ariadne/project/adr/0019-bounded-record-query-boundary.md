# Separate bounded record queries from admitted detail and metric authoring

**Accepted scoped Git-only amendment (2026-10-16):** [Specification 0027, written revision 1](../specs/2026-10-16-0027-core-git-only-authoring.md) retains catalog-bound ungoverned records and all complete-output safeguards, but retires public legacy serving and automatic ad-hoc metric staging. The bounded Core design is approved in chat; the owner approved the complete written revision and these amendments with “Schriftliche Fassung freigeben (Recommended)”; unaffected original approval remains.

Status: accepted (owner, Pi conversation 2026-10-08: approved the revised record-query and shared-safeguard design for specification/ADR/vocabulary capture, then approved the written specification revision 1). The owner subsequently requested ticketization of the plan's revision-1 S1–S3 decomposition; implementation, project admission and release/deployment publication remain gated.

A legacy project needs to retrieve a small set of trace events without turning the question into an aggregate, staging a metric or acquiring multi-fact graph admission. Add an explicitly ungoverned, catalog-bound **Ad-hoc Record Query** operation over one dataset. Keep admitted `query_detail` and its proven lookup/graph rules unchanged. Both routes use the existing compiler and shared Execution owner; no generic SQL, filesystem capability or second compiler is introduced.

**Alternatives:** extending admitted detail alone leaves the legacy request unsupported; a legacy mode inside detail mixes catalog projection with admitted graph traversal and makes truthful labels harder to preserve. Metric aggregation changes the requested record grain and cannot substitute for top-N events. A separate operation makes source access, artifact admission and result governance independently visible.

**Result boundary:** a successful computation is not yet a complete answer. Shared row, pre-transfer cell, serialized-response and deadline bounds must refuse an oversized result instead of returning an unmarked prefix. An output cap belongs after aggregate/window computation, never on its input rows. Query coordinates full core/selected-transport preflight before ad-hoc staging; output refusal leaves no Proposal even if calculation succeeded. This keeps the behavior consistent across CLI/MCP/native adapters rather than relying on a UI wrapper or increasing gateway limits. Output limits do not bound scanned data or repair the separately reported ad-hoc source-containment defect.

**Scoped consequences:** this adds a non-metric query route and amends older contracts' unbounded output and success-before-staging interpretation. It does not relax graph admission, source approval, grain safety, required Policy disclosure or human-only Promotion/Git Review Admission. No automatic legacy migration or fixed-role native Agent permission expansion follows. The [approved design specification 0014](../specs/2026-10-08-0014-bounded-record-queries-and-results.md) owns the approved API details, defaults, failures, compatibility and acceptance. The [revision-1 implementation plan](../plans/2026-10-08-0014-bounded-record-queries-and-results.md) is authorized for S1–S3 ticketization only; execution authority remains pending.
