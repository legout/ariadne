# Lumio public SDK 0.5.0

Release family: `lumio-wiki==0.5.0` and `lumio-lancedb==0.5.0`.
The adapter requires `lumio-wiki>=0.5.0,<0.6.0`. Both require Python >=3.14.
The private application is outside this public release.

Candidate release preparation for the `lumio-v0.5.0` channel tag in the
current `legout/ariadne` repository; the approved rename to `ariadne-lumio`
is pending a separately authorized cutover and no new URL is implied. These
notes describe the prepared candidate — they do not claim publication. No
numerical attestation, full-compliance or production-readiness claim is made.

## What is new

- **Optional S3 navigation over admitted pinned published contexts (#79).**
  The three scoped navigation operations — `list_published_context_pages`,
  `read_published_context_page`, `search_published_context_pages` — accept a
  keyword-only `metadata_store=None`, forwarded through the same shared
  exact-admission verifier as `open_published_context`. A pinned `S3Location`
  opens only with its explicitly supplied producer-side **private** metadata
  store; public objects alone never satisfy admission, and S3 publication
  never distributes private receipts. Plain directories, moving or current
  pointers, unpinned locations and S3 without the required store refuse
  explicitly before any store access. Local behavior, records, ranking and
  refusals are unchanged. Visibility scoping still applies before any
  selection, ranking, excerpts, counts or citations.
- **URL fetch deadline and truncation fixes.** Header reads can no longer be
  kept alive by trickled bytes past the overall fetch deadline, and a
  response body that ends short of its Content-Length is now an error
  instead of silently yielding partial content.
- **Internal simplification.** Knowledge base, source processing, Git
  authoring, S3 publish, CLI and MCP server internals were simplified and
  obsolete internal paths retired, with no public contract change.
- **Repository layout.** The Lumio product area now lives under
  `products/lumio/` in the shared Ariadne–Lumio monorepo (spec 0031):
  `products/lumio/packages/lumio-wiki`, `products/lumio/packages/lumio-lancedb`,
  `products/lumio/docs/`, `products/lumio/tests/`, `products/lumio/examples/`,
  `products/lumio/scripts/`, `products/lumio/eval/` and
  `products/lumio/experiments/`. Distribution names, import roots, CLI names,
  console scripts, extras and packaged resource locations are unchanged.

The 0.4.1 release carried navigation over admitted **local** Published
Versions only; that local-only baseline remains the documented behavior of
the published 0.4.1 pair and is identified here as historical.

## Migration

- The new `metadata_store` keyword is optional with a `None` default: every
  existing local-navigation call keeps working unchanged. S3 navigation
  that previously refused now opens when the producer-side private metadata
  store is supplied explicitly.
- The lockstep family moves 0.4.1 → 0.5.0 together. The adapter requires
  `lumio-wiki>=0.5.0,<0.6.0`; a family-crossing partial upgrade (for example
  `lumio-lancedb==0.5.0` with `lumio-wiki==0.4.1`) is rejected at install
  time by pip/uv resolution with a conflict naming both bounded ranges —
  never a runtime failure.
- No breaking change to any public contract; extras, CLI names and the
  packaged skill surface are unchanged.

## Optional extras

The base SDK stays model-free and cloud-free; capabilities remain opt-in:

- `lumio-wiki[documents]` — PDF/scanned-PDF/image and office-format
  conversion (LiteParse, MarkItDown, AnyDoc).
- `lumio-wiki[llm]` — unattended Distiller via an OpenAI-compatible
  provider (base wheel uses the host coding agent as Distiller).
- `lumio-wiki[s3]` — `obstore` for S3 Snapshot reading and the pinned S3
  locations (including the navigation above).
- `lumio-wiki[mcp]` — the read-only MCP stdio server over one Knowledge
  Base Location.
- `lumio-wiki[all]` — documents + llm + s3 + mcp together.
- `lumio-lancedb` — LanceDB/PyArrow retrieval adapter (base adapter).
- `lumio-lancedb[embeddings]` — local `sentence-transformers` embeddings
  (Torch stays out of the base adapter and out of `lumio-wiki`).
- `lumio-lancedb[s3]` — remote LanceDB index support over an immutable S3
  Published Version's `derived/lance/` prefix.

The SDK works without Ariadne, DuckDB, LanceDB, transport SDKs, models or
services unless a selected extra requires them; installing both products
never activates their integration. The optional LanceDB adapter stays
optional — `lumio_wiki` never imports it and there is no dependency edge
from the foundation wheel.

## Python requirement

Both distributions require **Python >=3.14** (unchanged).

## Known limits

- The Ariadne Context Profile is **metadata only**: it grants no source
  access, joins, SQL or numerical evidence. An ordinary documentation page
  is not a Core-validated technical Reference.
- S3 navigation requires the **exact pinned location identity** and the
  producer-side **private** `metadata_store`; there is no public-receipt,
  current-pointer or local-path fallback. Private publication metadata is
  not public Reader content.
- Integrated Core consumption of the S3 navigation requires a matching
  S3-capable Core release/build; the published
  `ariadne-data` 0.6.1 does not carry the Core-side S3 transport. A Core
  release carrying it is prepared as a separate later release — at the time
  of this candidate no such Core release has been published, and this
  release makes no claim about it. The SDK preserves producer-native
  metadata without gaining any new Core execution authority.
- The cross-role policy checks of the disposable S3-compatible test service
  require separately supplied test roles and remain unverified; this
  release certifies same-principal journeys only. No production-readiness
  or numerical claim is made.
- Verification limits of earlier releases (wheel-isolation scope, hosted
  CI as the required gate) continue to apply; see
  [0.4.1 notes](v0.4.1.md) and
  [packaging](../packaging.md).
