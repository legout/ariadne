# Lumio public SDK 0.5.1

Release family: `lumio-wiki==0.5.1` and `lumio-lancedb==0.5.1`.
The adapter requires `lumio-wiki>=0.5.1,<0.6.0`. Both require Python >=3.14.
The private application is outside this public release.

Candidate release preparation for the `lumio-v0.5.1` channel tag in the
current `legout/ariadne` repository; the approved rename to `ariadne-lumio`
is pending a separately authorized cutover and no new URL is implied. These
notes describe the prepared candidate — they do not claim publication. No
numerical attestation, full-compliance or production-readiness claim is made.

## What is new

This is a packaging-metadata patch on the 0.5.0 feature baseline — the
[0.5.0 notes](v0.5.0.md) remain the feature reference. There is no new API,
capability or runtime behavior:

- **PyPI presentation metadata fixed for both packages.** The package entry
  READMEs render as the PyPI long descriptions (`readme = "README.md"`), and
  the official Project URLs — Homepage, Documentation, Repository, Issues,
  Changelog — carry PyPI-safe absolute links into the canonical
  `legout/ariadne` repository. No repository rename is implied or performed.
- **No runtime change other than the version constant.** Both public packages
  move to 0.5.1 in lockstep; the adapter's dependency bound moves to
  `lumio-wiki>=0.5.1,<0.6.0`. The compatibility family stays 0.5.x.
- **How the fixed metadata arrives.** PyPI serves each version's metadata as
  published: the corrected presentation appears only with this new 0.5.1
  publication. The published 0.5.0 release stays exactly as it is — it is
  never replaced or deleted.

## Migration

- Nothing to migrate: no public contract, CLI name, extra or packaged-skill
  surface changes. Upgrading from 0.5.0 to 0.5.1 changes only the version
  constant and the adapter's lower bound.
- A family-crossing partial upgrade (for example `lumio-lancedb==0.5.1`
  with `lumio-wiki==0.4.x`) is still rejected at install time by pip/uv
  resolution with a conflict naming both bounded ranges.

## Optional extras

Unchanged from 0.5.0 — the base SDK stays model-free and cloud-free:

- `lumio-wiki[documents]` — PDF/scanned-PDF/image and office-format
  conversion (LiteParse, MarkItDown, AnyDoc).
- `lumio-wiki[llm]` — unattended Distiller via an OpenAI-compatible
  provider (base wheel uses the host coding agent as Distiller).
- `lumio-wiki[s3]` — `obstore` for S3 Snapshot reading and the pinned S3
  locations.
- `lumio-wiki[mcp]` — the read-only MCP stdio server over one Knowledge
  Base Location.
- `lumio-wiki[all]` — documents + llm + s3 + mcp together.
- `lumio-lancedb` — LanceDB/PyArrow retrieval adapter (base adapter).
- `lumio-lancedb[embeddings]` — local `sentence-transformers` embeddings
  (Torch stays out of the base adapter and out of `lumio-wiki`).
- `lumio-lancedb[s3]` — remote LanceDB index support over an immutable S3
  Published Version's `derived/lance/` prefix.

Installing both products never activates their Ariadne integration; the
SDK works without Ariadne, DuckDB, LanceDB, transport SDKs, models or
services unless a selected extra requires them.

## Python and license

Both distributions require **Python >=3.14** (unchanged) and are licensed
**Apache-2.0** (unchanged).

## Core pairing unchanged

Ariadne Core 0.7.0 is unchanged and is not republished by this release. The
qualified Core 0.7.0 integration pairing was tested with the SDK 0.5.0
family exactly (the Core release workflow pins the published
`lumio-wiki==0.5.0` wheel); this metadata-only 0.5.1 patch was not tested
by that workflow and does not by itself requalify the pairing. Consuming
0.5.1 with Core requires fresh validation and a new matching human
admission (see [ariadne-context](../ariadne-context.md)).
