# Declarative source registry with a shared connection builder

Status: accepted (owner, 2026-09-17 shape-design round for spec revision 9).

Every command previously attached a single SQLite file via `--db`. Source breadth lands as a declarative `ariadne.yaml` registry (sources: block) plus one shared connection builder that produces the DuckDB session for serve/author/validate/profiler: native table functions for csv/json/parquet (local and remote via httpfs), DuckDB extensions for delta/iceberg/ducklake, `postgres_scanner` attach for postgres, and the existing read-only SQLite attach. File globs become views so every source is addressable as `<source>.<table>` — envelopes, the compiler, the grain guard, and the audit operate unchanged over the unified connection. Credentials are env-var references (`connection_env`) resolved at runtime and never committed; a registry containing an inline connection string is a validation error. Validation is tiered by what DuckDB can fixture locally: live execution tests for sqlite/csv/json/parquet/delta, exact statement-construction tests for iceberg/ducklake/postgres/s3-https.

**Native DuckDB extension (owner approved written revision 1 with “approved.”, Pi conversation 2026-10-13):** [approved specification 0022](../specs/2026-10-13-0022-native-duckdb-sources.md) adds native local/HTTPS/S3 DuckDB files and views through this shared builder. [ADR-0022](0022-trusted-native-duckdb-catalogs.md) records the selected operator-trusted catalog boundary; neither read-only attachment nor source declaration supplies sandboxing, Source Approval or metric governance. No new execution backend is introduced. Execution decomposition belongs to its matching implementation plan; source access, target integration and publication remain separately gated.

**Named S3 profile extension (owner-approved in-chat design, 2026-10-14):** [specification 0025](../specs/2026-10-14-0025-named-s3-storage-profiles.md) adds credential-free named environment-reference profiles and temporary, non-intersecting scoped secrets to the same shared connection, including existing Lakehouse readers. [ADR-0023](0023-named-scoped-s3-storage-profiles.md) owns the trade-off. Effective endpoint identity extends Source Approval and measured/validated/admitted provenance; credential values never enter artifacts. The original statement-only remote test tier is not sufficient for the new credential-routing behavior: specification 0025 requires real S3-compatible fixture reads. Written-source review, planning and execution remain distinct gates; this notice grants no source access or publication.

**Considered options:** CLI-arg source lists (rejected — no project portability); auto-discovery of files (rejected — explicit registry only, no surprise sources); a separate sources.yaml (rejected — one project config).
