# Native DuckDB catalogs are trusted source definitions, not a sandbox or governed metrics

Status: accepted design decision (Owner, Pi conversation 2026-10-13: selected local plus HTTPS/S3 DuckDB sources and, after the trust-boundary question, “Geprüfte Kataloge” rather than a technical backing-resource allowlist). The owner subsequently approved the complete written specification 0022, revision 1, with “approved.” in the same Pi conversation. This architectural decision alone grants no source access, target integration or publication authority.

Ariadne will use its existing DuckDB registry/builder to attach native databases, including files containing only views. A view catalog stores executable source definitions and may read backing files or URLs. `READ_ONLY` is therefore a write-protection property, not a privacy sandbox, a data snapshot, or proof that a view is a governed Ariadne metric.

Decision: the first version supports **operator-reviewed trusted catalogs and their permitted backing-data accesses**. Preserve the existing human Source Approval, project/object permissions, credential boundaries and Query compile/authority gates. A proposed URI or uploaded catalog is not permission to open it; agents cannot approve its definitions or expand its permissions. Do not claim that the builder inspects or confines every transitive dependency inside arbitrary catalog SQL.

Considered alternatives: build a per-view backing-resource allowlist and enforce it before binding (deferred — requires a separate SQL/dependency analysis and enforcement design, not a small source-type addition); accept arbitrary unknown catalogs merely because the file is read-only (rejected — read-only does not isolate local files, network or credentials). The trust contract is deliberately explicit: later support for untrusted catalogs needs a new contract and may reject previously supported view constructs or require migration.

Observable behavior, registry compatibility, source inspection, remote prerequisites and acceptance criteria belong to [specification 0022](../specs/2026-10-13-0022-native-duckdb-sources.md), not this ADR. This extends [ADR-0010](0010-declarative-source-registry.md) without a new execution engine or raw-SQL query route. [Source Approval](../../CONTEXT.md) and [specification 0009 §5](../specs/2026-10-02-0009-modular-core-git-authoring.md) remain authoritative.
