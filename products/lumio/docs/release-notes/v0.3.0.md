# Lumio public SDK 0.3.0

Release family: `lumio-wiki==0.3.0` and `lumio-lancedb==0.3.0`.
The adapter requires `lumio-wiki>=0.3.0,<0.4.0`. Only these two public foundation
packages are released; the private application is excluded.

## Ariadne Context Profile and immutable SDK

This release adds the producer-owned versioned Ariadne Context Profile and
immutable captured/published context APIs. Metric, Policy and Reference
annotations retain native metadata and text, exact Namespace/Entity references,
finite typed Policy dependencies, visibility scope and snapshot-qualified
citations. Captured candidate validation uses the versioned
`ariadne_context.ontology_catalog` in `lumio.yaml`, not a later caller-provided
catalog. Native publication and managed destinations validate the same captured
inputs and retain distinct source-reference and publication-manifest identities.

This SDK preserves annotations; it does not authorize physical references,
joins, SQL, source access or numerical evidence. Ariadne owns its consumer
validation, admission and actual supported subset. `ariadne-data==0.5.0`
implements the local immutable Metric/Policy MVP; other producer profiles,
integrated KB bindings over S3 and wider integrated Analyst operations are not
thereby supported by that consumer.

## Installation and compatibility

Both packages require Python >=3.14. Install the base SDK alone when sufficient:

```sh
pip install 'lumio-wiki==0.3.0'
# Optional enhanced retrieval adapter, in the same compatibility family:
pip install 'lumio-lancedb==0.3.0'
```

The SDK base remains model-free, cloud-free and independent of Ariadne,
DuckDB, SQLGlot and LanceDB. Existing optional extras are unchanged. Do not mix
0.2.x and 0.3.x public-family members. Existing Git-native authoring/admission
and private Source boundaries remain; a Git commit alone never publishes a KB.

Code/build identities intentionally change on upgrade. Consumers binding exact
execution identity must explicitly revalidate/readmit instead of silently
relabeling an old admission as the new build. This is not a new numerical
attestation, hermetic replay or private-application qualification.

## Publication and limits

The established release pipeline verifies the exact built wheels, records
SHA-256 hashes and tagged-build provenance, and automatically publishes through
the environment-scoped PyPI token only after candidate gates pass. There is no
manual deployment approval; real KB/source adoption is still separately gated.
The private application, live model providers and unsupplied cross-role Source
permissions remain outside this public release's claims.
