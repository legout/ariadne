# Lumio public SDK 0.2.0

Release family: `lumio-wiki==0.2.0` and `lumio-lancedb==0.2.0`.
The adapter requires `lumio-wiki>=0.2.0,<0.3.0`. These are the two public
foundation packages; the private web application is not part of this release.

## Migration

**Breaking change:** Git-native authoring replaces the persisted Ingest
Proposal queue and proposal-facing publication APIs. Do not upgrade a consumer
that still depends on those APIs without migrating it first.

- Author and review ordinary Git worktree edits. Helpers do not implicitly
  commit, merge, admit or publish them.
- Use stable Entity IDs and exact Source Version SHA-256 pins in the
  `.lumio-authoring.yaml` Source Reference Manifest. Original source bytes,
  capture transcripts and private observations stay outside public Git content.
- Publication is a separate preview/confirmation of an exact revision, source
  bindings, retention choices, artifacts, destination and expected current
  version. A commit or merge alone is not publication approval.
- Source inspection in a native worktree follows the exact Entity/Source pin,
  not the registry's latest version. Published local/S3 versions use their
  sealed version-specific bindings. Missing exact bindings never fall back to
  newer source bytes.
- Inventory old stores with `lumio-wiki legacy-proposals inventory <kb>`.
  Legacy export has a read-only preview and a separate confirmation against the
  captured full baseline commit. It creates an **unadmitted Git branch**, not a
  publication or a new live proposal queue. Keep originals and review the result;
  never rewrite a real legacy store as an implicit upgrade step.
- Reactivation requires explicit Entity selection; title renames require an
  explicit alias choice. Unsupported compound-edit-plus-move operations refuse
  before applying effects.

See the [Quickstart](../quickstart.md), [KB format](../kb-format.md), packaged
`lumio-wiki` skill and `lumio-wiki --help` for the supported command surface.
The known private application's proposal-facing incompatibility is deferred;
this release does not certify that consumer.

## Optional extras

The base `lumio-wiki` package remains portable and model-free. It does not
require Ariadne, LanceDB, a web framework or a model provider.

- `lumio-wiki[s3]==0.2.0`: S3-compatible immutable publication and reading.
- `lumio-wiki[documents]==0.2.0`: optional document conversion.
- `lumio-wiki[llm]==0.2.0`: explicitly selected provider-backed operations.
- `lumio-wiki[mcp]==0.2.0`: optional read-only MCP server.
- `lumio-lancedb==0.2.0`: optional enhanced-retrieval adapter.
- `lumio-wiki[all]==0.2.0`: all core-package extras, not the separate adapter.

Install only the capabilities required by the application. Git is needed for
native authoring and admission, not for ordinary reading of a portable published
Knowledge Base.

## Supported Python

Both packages require **Python >=3.14**. Release validation targets CPython 3.14;
the declared minimum is not a claim that every newer interpreter was tested.

## Known limits

- The private web application and the joint Ariadne context profile are not
  included or certified. No shared integration ABI is approved by this release.
- Cross-role private Source metadata authorization requires separately supplied
  test roles. Without them it remains **unverified**. Authorized sealed metadata
  is distinct from optional retained raw bytes and is not automatic public access.
- No blanket type-clean or live-model-provider certification is claimed.
- Release uploads go directly to PyPI using one environment-scoped API token.
  Candidate checks, GitHub tagged-build provenance and SHA-256/byte verification
  remain enabled. PyPI digital attestations require
  Trusted Publishing and are not produced in this secret-only mode. Production
  promotion remains human-gated; see [packaging](../packaging.md#releases).
