# Separate OKF store for provisional answer examples

Status: accepted (owner, Pi design conversation 2026-09-29; storage boundary and six follow-up choices approved). The detailed interface and failure behavior are approved in [the feature specification](../specs/2026-09-29-0006-answer-examples.md) (revision 1).

Ariadne stores explicitly submitted, successful question/method/historical-answer examples in a **per-project OKF v0.2 sibling store**, not in the Context Layer: `staging/answer_examples/` for immediately discoverable, unapproved examples and `answer_examples/` under the selected served root for reviewed examples. A staged example is a labeled reference or hypothesis, never a governed definition or a cached answer. Reuse checks the current served metric/Policy and executes a fresh query; a changed cited metric or Policy suspends normal reuse of the old example pending review. Within one project checkout, submission is immediately discoverable; other checkouts see it only after ordinary repository synchronization.

This boundary was chosen over a `context_layer/examples/` subfolder because Context Layer search routes agents to business guidance and governed definitions, while a recorded answer is historical evidence that may be wrong or stale. Mixing them would make an unapproved example look like a rule and weaken ADR-0011's served-only context attachment. A separate database or service was rejected for the first local-first version: it would add synchronization and authority machinery without meeting an approved requirement for real-time sharing across machines. OKF keeps the existing file-backed provenance and review vocabulary without turning examples into Semantic Layer models.

**Scoped relationship to earlier decisions:** ADR-0003's human-only Promotion still governs served artifacts; *discoverability of a clearly marked staged example* is not Promotion or authority, just as `search_context` already exposes labeled drafts. ADR-0007's Context Layer taxonomy is unchanged. ADR-0012's local runtime remains the shared behavior behind local CLI and optional MCP. This feature uses its own review path, not an implicit extension of the Context Layer/OSI batch promotion gate. Approval of this ADR does not approve the proposed specification's unreviewed interface details or authorize implementation.
