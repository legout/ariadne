## Execution model

- Supervised, one sequential Pi writer in an isolated worktree under
  `${XDG_STATE_HOME:-$HOME/.local/state}/worktrees/`, following
  `orchestrate-implementation`.
- The base is the current `main` HEAD at dispatch. Pre-existing dirty files (e.g.
  `ariadne/init.py`) are not carried over.
- Each task stops at its owner gate. Proposals are tables in the run context, not new
  files in `project/`.
- Faults are injected only into a scratch copy of `src` (`test-diet` §4).
- Required gate: `.github/workflows/ci.yml` commands, run once per accepted batch
  candidate. Pytest for Lumio/root uses `-n 4`.

## Tasks

### T1 — Inventory and proof map (no-new-test, read-only)

Sources: spec §2 and §4.

- Collect cases, lines and slowest files per test root.
- Grep deletion-class signals: source reads, private access, `hasattr` absence checks,
  mocks, `sleep`/retry, and files named after rounds, issues or tasks.
- Map each spec §4 item to its candidate keeper tests. Mark tests whose sole subject is a
  surface 0037 removes as *defer to B*.

Done: a per-root inventory and proof map in the run context.

### T2 — Test-diet proposal per package (no-new-test)

Sources: spec §5 D1 and AC1/AC2.

Order: ariadne-data → lumio-wiki → lumio-workspace → lumio-lancedb →
`products/lumio/tests`, `integration/tests`, `tests/`. For each file:

- Classify each test.
- For each delete, merge or replace, name the survivor, its assertion, and the injected
  fault with its result.
- Record lines and runtime before and after.

**Owner gate:** approval of each package table before T3 touches that package.

### T3 — Apply the approved test-diet (existing-check)

Sources: AC1–AC3.

- Make small test-only commits per package or behavior.
- After each batch, run the touched tests. Before committing, rerun the full fault table
  against the final candidate.
- A survivor that misses its mapped fault blocks that deletion.

### T4 — Deslop proposal (no-new-test)

Sources: spec §5 D2.

- Per package, list dead, duplicate, overcomplex and slop candidates with their
  reachability evidence: entry points, MCP registrations, skill assets, dynamic
  imports.
- Exclude surfaces deferred to B.

**Owner gate:** approval of the candidate list.

### T5 — Apply deslop (existing-check)

Sources: AC3 and AC5.

- Work in incremental commits per package. Run focused tests after each change.
- Run stale-reference searches for deleted symbols.
- Check that wheel builds and install smoke checks still pass.

### V — Candidate verification and report

Sources: AC2–AC5.

- Run the full CI gate once on the final candidate.
- Re-run the §4 proof-map faults against the surviving tests.
- Report the counts from the spec's AC4, files removed or merged, suspicious tests kept,
  and any unverified items.
- Independent review follows the pasted reviewer contract. One fix pass, then one delta
  recheck.
- Then pause before integration.
