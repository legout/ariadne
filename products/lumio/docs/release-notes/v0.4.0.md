# Lumio public SDK 0.4.0

Release family: `lumio-wiki==0.4.0` and `lumio-lancedb==0.4.0`.
The adapter requires `lumio-wiki>=0.4.0,<0.5.0`. Both require Python >=3.14.
The private application is outside this public release.

## Scoped navigation over immutable local knowledge

The public `lumio_wiki.ariadne_context` functions
`list_published_context_pages`, `read_published_context_page` and
`search_published_context_pages` include visible ordinary pages alongside
profiled pages. They require an admitted, immutable, version-pinned
`PublishedFilesystemLocation` and matching `ContextIdentity`; plain directories,
moving pointers and S3 navigation refuse. Scope is applied before selection,
ranking, counts, excerpts and citations. Lists contain metadata, reads retain
canonical content, and search reuses the native ranking engine with separately
labelled verbatim evidence and inclusive canonical line coordinates. Escaped
YAML values and multiline CRLF metadata retain their actual source passages.

The existing `open_published_context` profile reader is unchanged in scope:
its pinned admitted local/S3 inputs remain supported under its own contract.
Navigation adds no service, model provider or new source-access authority.
See [the SDK integration reference](../ariadne-context.md) for exact imports.

## Paired Ariadne consumer

The consumer pairing is `ariadne-data==0.6.0` with
`lumio-wiki==0.4.0`. Install the adapter only when enhanced retrieval is needed:

```sh
pip install 'ariadne-data[mcp]==0.6.0' 'lumio-wiki==0.4.0'
# Optional public-family adapter:
pip install 'lumio-lancedb==0.4.0'
```

Exact source commits, wheel hashes and qualification evidence identify the pair;
a version string alone never substitutes for the installed build identity.
The SDK base stays independent of Ariadne, DuckDB and SQLGlot.

Git/local sync transports authored content and never activates it. Ariadne alone
validates its supported Metric/Policy/Reference subset, authentic native evidence
and source approvals, then requires exact overall human admission. Source-backed
manual assertions retain their existing native eligibility; producer-authored
inline evidence never becomes a Core inspection receipt or human confirmation.
Neither navigation nor a confirmed mapping authorizes a join or SQL transform.

## Upgrade and publication boundaries

A code or package build change requires genuine Core revalidation and a fresh
matching admission; old Bound Releases are never relabelled as a new build.
Existing sessions remain pinned to their admitted version.

The existing tag pipeline builds and verifies the public wheels before automatic
PyPI publication. No private application, production KB, live model or full Core S3
integration is qualified by this release.
