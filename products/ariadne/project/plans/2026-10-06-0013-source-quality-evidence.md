## 2. Profile and shared output contract

### Authored metadata

Use a new root frontmatter key `ariadne_quality` on a `type: table` page. It is separate from system-owned `ariadne.schema`/`ariadne.observations`, the canonical `resource`, and `context_signals`. Shape: `{version: 1, reports: [...]}`. Ordinary pages without it retain their existing behavior.

Each report has the following closed key set; only fields marked optional may be absent:

- `id`: nonempty stable string, unique within the page; `asset`: the exact canonical table `resource`, equal to the containing page's core binding.
- `source_ids`: nonempty list of IDs resolving to the page's existing `sources` citations with nonempty `resource`. A citation is not permission to open its URI/file.
- `scope`: `{kind: asset|subset, description, population, period}`. Description/population are nonempty supplied text. `period` is null for explicitly non-time-bounded evidence, otherwise `{field, start, end}` with an exact physical-field identity and aware instants, `start < end`, interpreted as `[start, end)`. Subset text alone never proves query correspondence.
- `reported_at`: aware instant; optional `observed_at`: aware instant when separately supplied. Without observation time, disclose only report time, never invent when a measurement ran.
- Optional `source_version`: `{kind: snapshot|version, value}`; optional `provenance`: supplied nonempty text; optional `reported_by`, `cadence`: supplied nonempty text. Available version/provenance remains supplied, not authenticated by admission.
- Optional `valid_until`: aware instant, no earlier than `reported_at`.
- `checks`: nonempty list of `{id, kind, outcome, criterion, tested_population, tested_period}`. IDs are unique within the report; `kind`, criterion/population are nonempty text; `outcome` is exactly `pass|fail|unknown`; `tested_period` uses the same period-or-null contract. A completeness claim must identify its tested population/criterion and period or explicit non-time-bounded scope; “healthy” alone is not a meaningful reviewed claim.
- Optional `watermark`: `{kind, value, field, meaning, units, timezone, observed_at}`. `kind` is `event_time|ingestion_time|snapshot_as_of|other`; value is a finite JSON scalar, other fields are supplied nonempty text, observation is aware. Temporal kinds require an aware instant value and declared timezone/units; `other` retains its stated scalar meaning without inventing temporal/completeness semantics.

Reuse the accepted shared instant normalization where suitable, but new required structured timestamps must carry timezone/offset. YAML-native aware datetimes normalize to JSON strings; naive datetimes, plain dates and malformed required instants are rejected rather than silently assigned UTC. Optional absence is not invalid evidence; invalid present content is not optional absence. A report/observation later than the assessment instant has unknown age and a `report_time_in_future` limitation, not a claim that its check has already run.

Reject unsupported versions, unexpected profile/report/check/watermark keys, malformed values, duplicate IDs, mismatched asset/citation identity and executable payload fields (`sql`, `script`, `command`, etc.). Descriptions are inert explanatory text, never parsed/executed as instructions. Existing `_refuse_forged_claims` continues to prevent edits to core-owned observations/resource; do not put the authored extension under its protected `ariadne` block. Validation establishes shape/binding, not real quality or business truth.

**Finite bounds:** at most 8 reports/page, 8 checks/report, 8 source IDs/report; ID/version/field/actor strings at most 128 characters, description/criterion/population/meaning/provenance at most 1,024, cadence at most 256, units/timezone at most 64. The normalized profile's UTF-8 JSON is at most 8 KiB. These bounds apply to new metadata, not existing schema/Policy bodies or numerical result limits. These and the reader/output budgets below are approved behavioral/public-contract limits, not derived mechanical budgets. The worker's mechanical-conflict allowance never authorizes raising them to fit code/tests.

### `data_signals` view

Applicable operations are `get_metric` and `query_metrics`: each receives one additive top-level `data_signals`. `query_metrics` associates every retained metric entry with its identified dependencies, sharing asset/report entries rather than duplicating them. Existing `context`, `context_signals`, admission, rules, SQL, rows and labels are unchanged. Discovery, ad-hoc operations and `query_detail` keep their current envelopes; they do not acquire quality evidence/authority under this first metric-answer slice. No request/tool argument changes.

The view has the closed keys `version: 1`, `assessed_at`, `metrics`, `assets`, `warnings`, `truncated`, `omitted`:

- `metrics`: entries `{name, assets, coverage}`, with canonical asset references. Coverage is `complete|partial|unknown`: complete means all direct dependencies are identified/cited and have applicable parseable report evidence, **not** that data is healthy; partial means identified coverage is incomplete; unknown means dependency correspondence cannot be established. An expired or reported-failed report can still cover an identified dependency.
- `assets`: entries `{resource, page, coverage, reports}`, using the same coverage enum: complete for exactly identified applicable report coverage, partial when bounds omit otherwise identified report coverage, unknown when correspondence/evidence is unavailable. Unknown/unavailable paths are null, not guessed. Reports retain the normalized supplied fields above plus `evidence_kind: supplied`, `age: as_of|expired|unknown`, `applicability: applicable|inapplicable|unknown`, and `limitations` code strings. `as_of` means only available unexpired as-of evidence, never live healthy. Missing validity leaves age unknown with the supplied as-of timestamps still visible.
- `warnings`: entries `{code, metric, asset, page, report}`; nullable identity fields only where genuinely unavailable. Codes are `data_report_failed`, `data_report_expired`, `data_report_inapplicable`, `data_applicability_unknown`, `data_coverage_partial`, `data_evidence_unavailable`, `data_signals_truncated`. Missing optional owner/cadence/validity alone does not create a warning. A wholly absent optional quality profile discloses unknown coverage without a warning merely for its absence; partial supplied coverage, unreadable declared evidence or materially unresolved correspondence may warn. An inapplicable report is disclosed as inapplicable, never as a failed/passing check of the requested data.
- `omitted`: counts for metrics, assets, pages and reports; `truncated` cannot be false if any bound prevented assessment/disclosure. Elided evidence never leaves a complete/warning-free quality claim.

Known version/scope contradiction makes applicability inapplicable. Report `limitations` use the closed codes `source_version_unknown`, `source_version_mismatch`, `scope_unknown`, `scope_mismatch`, `report_time_in_future`, `validity_not_supplied`, `binding_unknown`, `citation_unavailable`, `metadata_unavailable`, `metadata_invalid`, `truncated`. Matching requires mechanically established correspondence from existing source/query facts; free-text scope does not match by similarity. Missing source-version evidence or unresolved subset correspondence is an explicit limitation/unknown applicability. A registry/admission digest is not a dataset version. An asset-wide report describes only its identified asset/as-of scope; it is not a claim about an unrelated station, time or snapshot. A recent event watermark and reported completeness failure remain separate facts.

**Reader/output bounds:** at most 64 metric entries, 64 asset references, 32 directly cited table pages and 128 report entries per operation; read at most 64 KiB of frontmatter per table page, never its external citations/body lineage. The total added `data_signals` UTF-8 JSON is at most 64 KiB per operation. Use deterministic order and one shared budget/assessment instant/local page cache for multi-metric work. Missing/oversized/malformed advisory metadata becomes explicit unavailable/partial evidence; preserve containment/source/admission refusals. Metadata budgets cannot truncate numerical results, policies or old context payloads.
