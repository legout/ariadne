# ADR-0026: Lumio SDK and atomically bound governed releases

Owner-approved direction, Pi conversation 2026-10-18 for Ariadne #76/Lumio #2:
one Content Repository, a direct optional Python SDK, integrated-only strict
mandatory Policies, one overall human confirmation and project-wide Visibility
Scope defaulting to public. The owner selected “Design freigeben (Recommended)”
for the complete six-section V1 design and documentation capture. The
[written specification 0029](../specs/2026-10-18-0029-lumio-bound-governed-releases.md)
was subsequently approved with “Schriftliche Fassung freigeben (Recommended)”
on 2026-10-18, together with both specifications, ADRs, glossaries and scoped
source amendments. This opens planning, not execution, integration or release authority.

Use one exact jointly reviewed content commit without merging the software
repositories. Lumio remains authoritative for curated knowledge; Ariadne remains
authoritative for contracts, OSI, observations and execution. Consume the
versioned Lumio profile through its optional SDK rather than a lossy generic
OKF round-trip, separately maintained copy or new service.

Overall human admission binds the real native publications/reviews, exact
knowledge/analytics/execution identities and operator Visibility Scope. Activate
the extended Core admission descriptor last and atomically. Integrated readers
use that binding, never an independently moving Lumio current pointer. This
preserves native admissions without inventing a distributed transaction or
third workflow store; a completed standalone publication can remain after a
failed overall activation and must be disclosed.

Only the integrated route refuses missing/mismatched required Policy Closure
before SQL. Standalone retains ADR-0011/spec 0011's advisory fallback. Policies,
Aliases and ontology links still grant neither calculation nor join authority;
Source Approval remains a separate human permission.

## Local delivery-scope refinement (2026-10-19)

After the initial A1 failure/review, the owner selected a local Metric
through-slice and a strict profile boundary, then approved writing the complete
six-part MVP design with “So ausarbeiten (Recommended)”. The owner subsequently
approved written spec0029 r2 and scoped notices with “Schriftlich freigeben
(Recommended)” on 2026-10-19, opening local planning only. This is not a new
implementation or publication grant and does not change the accepted producer.
The owner later separately approved M1 execution with “Plan + M1 starten
(Recommended)”; plan0029 r8 owns that limited grant, not the full target.

Keep the repository, SDK, human consent, exact identity, Visibility Scope and
atomic-last activation decisions above. First support local immutable Versions,
Metric/Policy profiles, `get_metric` and source-free admitted catalog/capability
disclosure. Other integrated Analyst operations and unsupported Ariadne
application kinds/extensions refuse; standalone remains unchanged. S3,
multi-metric/Context operations and additional annotation semantics remain
full-target work, not waived guarantees.

The strict boundary is chosen over a partially validated projection: an
unsupported Ariadne profile anywhere in the captured KB refuses instead of
leaving an ambiguous “Core-validated” subset. Ordinary unprofiled Lumio pages
remain KB content. This keeps one honest consumer contract without losing
producer bytes or claiming nonexistent reference/evidence validation. Delivery
staging is reversible through separately reviewed support and a new matching
admission; it does not warrant a second architecture ADR. The full #76/#79
goals and qualification obligations stay open.

## Alternatives and consequences

A separate content repo is chosen over independently moving content repos so
one domain change has one Git revision/diff. A direct SDK is chosen over a
portable profile bundle or Provider service; this trades integrated runtime
package coupling for one producer implementation and no service. Core's base
install remains independent; exact SDK/build compatibility becomes an admission
binding.

Global strictness would break standalone contracts, so strict closure is
explicitly project/admission-bound, not an Agent flag. One overall confirmation
is chosen over three manual approvals, but it must display and bind every
authorized native side effect. Existing source permissions, private storage
boundaries and operator-only authority remain.

The Lumio producer side is owned by its ADR-0030/spec 0009, not a second copied
profile schema here. Historical numeric replay and simultaneous activation of
all standalone readers are not promised.
