# Keep ODCS producer contracts separate from native consumer bindings

Status: accepted design decision (owner, Pi conversation 2026-10-17: selected immutable ODCS v3.2.0, strict official-schema validation, separate local Git bindings, bounded DuckDB-quality execution and live-evidence-gated admission; then approved the complete in-chat design with “Design freigeben (Recommended)”). The owner subsequently approved written specification 0028 revision 1, this ADR and the glossary with “Schriftliche Fassung freigeben (Recommended)”. This records planning authority, not implementation, source-access, integration or publication authority.

Keep producer-owned ODCS documents unchanged by observation. Store Ariadne's explicit source/OSI bindings separately in the same native Git candidate, and retain Core-produced as-of observations in existing operational validation evidence. Contract intent, consumer configuration, measured state and human admission have different owners: inferring one from another would let source drift rewrite expectations or let a contract's server declaration become an access grant. Support an explicitly limited pinned consumer profile, not a claim of complete ODCS semantics.

Embedding bindings in producer `customProperties` would couple consumer deployment choices to producer revisions. Waiting for a shared Lumio ABI would unnecessarily block this native slice, while inventing that ABI locally would bypass the joint #76 gate. Use existing native selectors and scoped producer IDs now; portable cross-layer identity/provider integration remains separately approved work. Explanatory knowledge stays with its existing owner; an ODCS statement never becomes an executable Policy, join authorization or cached numerical answer.

[Specification 0028](../specs/2026-10-17-0028-odcs-contract-consumer.md) owns the exact format, supported checks, outcomes, limits and admission behavior. [ADR-0017](0017-context-schema-and-identifier-knowledge.md), [ADR-0023](0023-named-scoped-s3-storage-profiles.md) and [ADR-0024](0024-git-only-durable-authored-state.md) retain their knowledge, source-permission and Git-lifecycle boundaries.
