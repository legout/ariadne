# OKF bundle structure for context_layer + agent-authored bundle generation

Status: accepted (owner, 2026-09-15 shape-design round for spec revision 6).

**Context-profile scoped amendment (owner, 2026-10-02):** [specification 0010](../specs/2026-10-02-0010-context-layer-schema-and-identifiers.md) and [ADR-0017](0017-context-schema-and-identifier-knowledge.md) add Dataset Overviews, general structured References, source-qualified generated schemas and claim-level citations. Applicable-page/dependency validation replaces mandatory six-category presence; unknown physical-table Grain is permitted without relaxing declared semantic Grain or live checks. New freshness timestamps use explicit offsets, and reviewed hypotheses remain distinct from confirmed mapping assertions. The new Git route retains pre-review finalization rather than post-admission decoration.

**Later scoped amendment (owner, 2026-10-02):** the [Git-backed authoring design](../specs/2026-10-02-0009-modular-core-git-authoring.md) retains OKF and service-owned generated content, but finalizes generated artifact bytes before candidate validation/commit review. Approval evidence is recorded separately rather than decorating the admitted commit afterward. This supersedes post-review artifact mutation only for the new Git authoring route; legacy staged Promotion keeps its existing bookkeeping.

The context layer adopts the OKF v0.2 bundle structure as implemented by the reference bundles: typed folders (`tables/`, `references/joins/`, `policies/`, `metrics/`, `computations/`, `skills/`), an `index.md` in every directory plus the root (SPEC §8 progressive disclosure), a `log.md` change log, and the full trust/lifecycle frontmatter (`generated`/`verified` list/`status`/`stale_after`/`sources`), extended with `grain` and `governed_by` blocks per ADR-0006 §4.1. Business rules currently embedded in metric pages and seed notes are extracted as `policies/` pages that metrics cite. The enriched bundle is generated by `author.py` (profile + seed notes + models), not hand-authored — chosen because the authoring loop is the product's core IP; a hand-authored bundle would demo the format without exercising the product. Promotion becomes mechanical bookkeeping in `scripts/promote.py` (merge-only, appends `verified`, regenerates indexes, logs).

**Considered options:** hand-authored demo bundle first (rejected — demos the format, not the loop); metrics-only context layer (rejected — tables, joins, and policies are where the demo's answers actually came from).

**Scoped extension (owner, 2026-09-24):** [Harness-led authoring](../specs/2026-09-24-0005-harness-led-authoring.md) uses the harness's model but retains server-owned bundle checks. A computation for a new metric with no independent expected-value oracle declares `attestation: pending` instead of attributing it to the demo's `tests/test_evals.py`; human review and compile/grain validation are not independent numeric attestation.
