# Harness-led authoring with server-owned checks

Status: accepted (owner, pi session 2026-09-24; approved with written harness-led authoring specification revisions 1–2).

**Measured-knowledge scoped extension (owner, 2026-10-02):** [specification 0010](../specs/2026-10-02-0010-context-layer-schema-and-identifiers.md) adds bounded, typed equality/prefix/lookup inspection and automatic hypothesis capture in Git proposals. The core owns measurement receipts; operator-approved access/sample limits and exact-revision human confirmation remain binding. A sampled match, persisted hypothesis or admitted investigative page is not business-meaning approval.

**Later scoped amendment (owner, 2026-10-02):** [ADR-0016](0016-modular-core-git-authoring.md) replaces the single full-bundle staging slot and complete-resubmission workflow with independent model/page edits in concurrent Git-backed authoring proposals and pinned-revision human admission. The [new specification](../specs/2026-10-02-0009-modular-core-git-authoring.md) owns that lifecycle. Harness-model ownership, operator source/document access, deterministic checks and honest pending attestation remain binding; the amendment does not authorize implementing or deploying HTTP MCP.

The agent harness's own model should interpret database profiles and domain documents, propose Seed Notes, and author OSI/OKF; Ariadne should measure data, convert source documents, validate and stage the proposal. This works locally through a skill/CLI or stdio MCP and remotely through private HTTPS MCP with a server-held bearer token against one server-configured project. A bearer token was chosen over proxy-network identity or OAuth for the initial single-user deployment because it keeps access enforcement explicit without adding an identity system. We choose this over allowing direct agent writes (which bypasses bundle checks) or routing every authoring job through `ariadne-author`'s server-configured LLM (which does not use the harness's model). The server opens a newly proposed dataset location only after an operator approves its registry entry; the model may receive the approved full profile and converted evidence, but not source credentials. Proposed business rules remain unverified until the human reviews the exact Seed Notes and artifacts and explicitly Promotes them. A newly modeled metric without an independent expected-value oracle may be human-reviewed and Promoted, but its computation must state that independent attestation is pending; compile and grain checks or the demo's `tests/test_evals.py` cannot be presented as its oracle.

This extends ADR-0009's separate-document-ingestion decision only for an explicitly requested harness-led authoring workflow, and makes an honest pending-attestation exception to ADR-0007's bundle contract for new metrics; ordinary ingestion remains standalone. It preserves ADR-0003's human-only **local Promotion** gate and ADR-0012's local-first default while adding optional remote authoring. The later production Git-review admission decision is scoped in [ADR-0003](0003-staging-dir-review-gate.md); neither route lets the agent approve its own proposal. Interface, failure, and acceptance details belong to [the approved specification](../specs/2026-09-24-0005-harness-led-authoring.md); its approval does not authorize implementation.
