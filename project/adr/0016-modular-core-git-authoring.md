# Shared core modules and Git-backed authoring proposals

**Proposed scoped Git-only amendment (2026-10-16):** [Specification 0027, written revision 1](../specs/2026-10-16-0027-core-git-only-authoring.md) captures the owner-approved bounded Core direction; its written review is pending. The retained standalone-ingest/ad-hoc/Example/legacy exceptions retire: ad-hoc execution is ephemeral, explicit persistence uses native Git, Examples use common admission, and legacy migration is excluded by the owner. Unaffected original approval remains; no implementation or shared #76 contract is approved by this notice.

Status: accepted (owner, Pi conversation 2026-10-02: approved the complete in-chat design after selecting independent model/page editing, breaking-interface permission, split plus combined MCP toolsets, and local Git-backed proposals now). Design approval is not implementation or publication authorization.

**Later scoped extension (owner, 2026-10-02):** [specification 0010](../specs/2026-10-02-0010-context-layer-schema-and-identifiers.md) and [ADR-0017](0017-context-schema-and-identifier-knowledge.md) extend the Context profile with Dataset Overviews, general structured References, generated schemas, terminology resolution and bounded mapping inspection. They also allow human-admitted context-only revisions before metrics exist; full applicable checks and separate mapping confirmation still bind the exact reviewed revision. Shared-module ownership, source approval and the Git lifecycle below remain authoritative. The earlier plan/tickets require separately authorized reconciliation before consuming this added scope.

**Later scoped Query extension (owner, 2026-10-08):** [ADR-0019](0019-bounded-record-query-boundary.md) and [specification 0014](../specs/2026-10-08-0014-bounded-record-queries-and-results.md) add catalog-bound ungoverned record selection and shared output/deadline safeguards. Query coordinates complete core/transport preflight before ad-hoc staging; Execution remains the connection/collection owner. No graph admission rule, source approval, Git lifecycle, legacy project state or native Agent permission set is relaxed. Existing plans/tickets do not acquire this scope automatically.

Keep one `ariadne-core` distribution, separating Authoring and Query workflows from DuckDB Execution and shared Sources, Semantic, Context and Proposals modules. Both workflows need the same artifact meaning, compiler and checks; duplicating them by agent role or MCP server would make governance and results diverge. Analyst remains a user-facing role/toolset; retrieval is one responsibility inside Query. DuckDB, SQLGlot, OSI and OKF remain unchanged.

Use Git-backed authoring proposals with separate branches/worktrees and independent model/page edits instead of extending one mutable full-bundle staging slot or building bespoke branching/merge machinery. Validate the effective candidate, review its exact revision, and serve only a pinned human-admitted revision. Source approval remains a separate operator decision; commits, validation and review are not interchangeable. Approval evidence stays outside reviewed artifact bytes, with generated artifact content finalized before validation. Start with local Git; hosted GitHub/GitLab integration is deferred.

**Alternatives:** a smaller extraction of execution/context would leave workflow ownership unclear; per-role implementations or separate distributions would duplicate shared rules and complicate installation. Retaining one active proposal per project would obstruct independent Git workflows. Building native execution backends or adopting Ibis now was deferred in favor of the current DuckDB path.

**Scoped consequences:** for the new Git-backed full-bundle authoring workflow, this supersedes ADR-0003's local staging-only admission route, ADR-0013's single active full-bundle slot and complete-resubmission requirement, and ADR-0007's post-review artifact decoration. It replaces ADR-0012's single-runtime ownership with shared core modules, preserving transport neutrality and optional MCP. Standalone ingestion, staged ad-hoc definitions and the separate Answer Example store retain their own review/staging contracts; existing unreviewed files do not acquire Git admission automatically. The separately installed Agent's fixed-role session contract remains unchanged. The [approved design specification](../specs/2026-10-02-0009-modular-core-git-authoring.md) owns behavior, migration requirements and acceptance.
