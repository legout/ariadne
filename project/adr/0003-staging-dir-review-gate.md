**Accepted scoped Git-only amendment (2026-10-16):** [Specification 0027, written revision 1](../specs/2026-10-16-0027-core-git-only-authoring.md) captures the owner-approved bounded Core direction; the owner approved the complete written revision and these scoped amendments with “Schriftliche Fassung freigeben (Recommended)”. The new-project-only Core slice retires the remaining staging/Promotion route in favor of common exact-revision Git Review Admission; no legacy migration or user-file deletion is authorized. Unaffected original approval remains; no implementation or shared #76 contract is approved by this notice.

Status: accepted (owner, 2026-09-14 shaping session; single-user real-document scope clarified by owner, 2026-09-23; production Git-review route approved by owner, 2026-09-30).

**Context-only scoped extension (owner, 2026-10-02):** [specification 0010](../specs/2026-10-02-0010-context-layer-schema-and-identifiers.md) permits human Git Review Admission of a context-only revision before the first metric, with full matching evidence for every applicable check. Admitting an investigative Reference does not confirm its mapping hypotheses; asserted mapping confirmation is separately exposed and bound to the exact reviewed revision. No agent admission or automatic legacy migration is introduced.

**Later scoped amendment (owner, 2026-10-02):** [ADR-0016](0016-modular-core-git-authoring.md) and the [modular-core specification](../specs/2026-10-02-0009-modular-core-git-authoring.md) replace staging-only local admission for the new Git-backed full-bundle authoring workflow with exact-revision human Git Review Admission. The legacy route below remains applicable to existing staged workflows, standalone ingestion and the separate Answer Example store; no existing files become Git-admitted automatically. Hosted Git/production deployment automation is not part of the new local workflow.

The research study (§8) proposes pull requests as the human review gate. For a single-user **dev/test** project, including real documents ingested under ADR-0009, the gate remains `staging/` followed by explicit human Promotion: no agent may directly serve a proposal. Promotion already appends `verified` history and updates the bundle log (ADR-0007); it is not deferred until real data arrives.

For **production semantic models**, including multi-fact definitions, the owner approved a second admission route: a human-reviewed Git change (such as an approved PR) **and** a passing full validation report bound to the same commit and artifact digest. The deployment serves that reviewed revision, not arbitrary working-tree files. A commit or validation result alone is not review, and the production route does not call local Promotion. Both routes feed the same served artifact format and runtime; neither lets the authoring agent approve its own proposal. The [multi-fact planner specification](../specs/2026-09-30-0008-multi-fact-planner.md) owns the exact admission behavior. This scoped production decision preserves the lightweight local gate without pretending that KTX's recommended Git workflow is an enforced runtime check.
