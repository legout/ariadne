# Standalone proposal-first document ingestion

**Proposed scoped Git-only amendment (2026-10-16):** [Specification 0027, written revision 1](../specs/2026-10-16-0027-core-git-only-authoring.md) captures the owner-approved bounded Core direction; its written review is pending. Standalone conversion/Verbatim/consent rules are retained, but derived artifacts go into an explicitly selected Git candidate and private originals remain operator-managed external inputs; no Core upload/retention store remains. Unaffected original approval remains; no implementation or shared #76 contract is approved by this notice.

Status: accepted (owner, 2026-09-17 shape-design round for spec revision 8; inspired by the lumio-wiki Knowledge Base flow).

**Structured-Reference scoped extension (owner, 2026-10-02):** [specification 0010](../specs/2026-10-02-0010-context-layer-schema-and-identifiers.md) preserves approved aliases/scoped binding metadata and actual document provenance through this ingestion route. Document claims cannot fabricate measured receipts, register/open newly mentioned data locations or confirm identifier equivalence. Standalone staging, human Promotion and opt-in approved-Policy reconciliation remain unchanged.

Documents (notes, PDFs, data dictionaries, office/HTML files) enter the context layer as standalone proposals via `ariadne-ingest`, not as author-loop inputs: convert to Markdown (native md/txt; the `[documents]` extra — liteparse, markitdown[docx], firecrawl-anydoc, the stack researched in lumio-wiki — for PDF/office/HTML; per-format dispatch: PDF and HTML via the converters that verified-live support them, legacy office/epub/csv via firecrawl-anydoc), LLM-distill into typed OKF pages classified into the existing bundle taxonomy (unclassifiable content defaults to `references/` with an ingest tag), enforce the per-type frontmatter contract at staging, cite the source document in `sources[]` with digest and path, and stage under `staging/context_layer/` — the existing promote gate remains the only path to served state. Chosen over an author-input channel (documents woven into bundle authoring) because it reuses promote.py and the bundle gate unchanged, gives immediate per-document value without re-authoring, and keeps the author loop's seed-notes input contract stable; the author-input widening remains possible as a later revision.

**Consequences:** the LLM classifier decides page type within the contract — wrong classifications are caught at the per-type gate or by the human at promotion; the `[documents]` extra stays optional so the base install remains lightweight.

**Scoped extension (owner, 2026-09-24):** [Harness-led authoring](../specs/2026-09-24-0005-harness-led-authoring.md) may explicitly use converted documents as evidence while the harness drafts Seed Notes, OSI, and OKF. This does not change ordinary standalone `ariadne-ingest` or its separate opt-in approved-Policy reconciliation.

**Opt-in comparison clarification (owner, 2026-09-23):** Re-ingestion may compare an exact-path proposal against a served Policy under the existing human Promotion gate (ADR-0003). Sending approved Policy text to the configured ingestion model is permitted only when the operator explicitly requests reconciliation; ordinary ingestion does not disclose it. Model conflict suggestions remain advisory, never approval or a hard promotion gate. This boundary was chosen over automatic Policy egress or model-decided replacement to preserve the single-user local flow and make the added disclosure deliberate. The observable comparison contract belongs to [the reconciliation specification](../specs/2026-09-23-0004-evidence-reconciliation.md).

**Optional no-distillation extension (owner approved written revision 1 with “approved.”, Pi conversation 2026-10-13):** [approved specification 0021](../specs/2026-10-13-0021-verbatim-document-ingestion.md) adds Verbatim Ingestion using existing converters, one preserved document Reference and the same standalone staging/human gate. Ordinary ingestion remains LLM-distilled; this direction neither adds automatic classification/authority nor combines Verbatim with reconciliation. Execution decomposition belongs to its matching implementation plan; target integration and publication remain separately gated.
